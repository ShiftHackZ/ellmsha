# eLLMsha — November 2, 2026 · Patch 3

## New

- Connect multiple Figma accounts independently in Settings → Plugins → Figma. Each account has its own verified identity and tools for reading designs and nodes, exporting images, browsing folders and managing authorized comments.
- On desktop, your agent can help connect the Figma account signed in to the in-app browser. Personal access tokens move through a private import flow; they do not appear in tool arguments or results. Manual token setup also works in WebUI and Docker.
- Interactive terminal tabs are shared by you and your agent. Type commands, inspect live output, use full-screen tools such as `watch`, send Ctrl+C, resize the terminal, or close the session and its owned processes. Desktop terminals run locally; WebUI terminals run on the server, inside the container for Docker deployments.
- Open file and BMAD document previews refresh after source changes while preserving the selected tab and unsaved edits. A toolbar button beside Files shows or hides the preview panel without closing its tabs.

## Improvements and fixes

- Figma uses its official full-color logo in the plugin list and account settings.
- Settings → Memory separates Memory Hub from embedding-model settings and preserves unfinished configuration when switching tabs.
- The update icon appears only when a newer release is available.
- Fixed the blank USB security-key dialog in the macOS in-app browser. Cancel, Escape and native close remain available when its renderer fails to start.
- Improved Copilot tool compatibility and shared project-rule preloading across agent runtimes.
- Fixed Windows archive asset checks and preserved the release date format in installer filenames.
- Desktop, WebCLI and Docker builds include Figma, shared terminal tools and their required runtime resources.

## Support notes

- The Figma plugin uses personal access tokens and the REST API. It supports design inspection and exports; arbitrary canvas editing and official Figma MCP-only tools are outside its scope. Comments require the normal approval flow.
- The terminal manages processes created through its own sessions; it does not adopt unrelated external processes.
- macOS Apple silicon installers are Developer ID signed and notarized. The Windows x64 installer is unsigned; native Windows installation/runtime checks remain separate from package verification.
